## รูปแบบไฟล์

- `manifest.json` — schema, dictionary สำหรับ decode ค่า `_id`, template ของงวด และ metadata ของ source
- `boq_data_001_016.json` ... `boq_data_145_160.json` — ข้อมูลครบ 160 แปลง แบ่งเป็น 10 partition
- แต่ละ plot มี metadata, `ten_year_total_baht` และข้อมูลปี 1–10
- แต่ละปีเก็บ `annual_value_baht`, งวด 1–4 และ flag `is_exception_to_header_template`

### Grain ที่แนะนำสำหรับ dashboard

ใช้ `plot_code` เป็น key ระดับแปลง และ `contract_no` เป็น key สำหรับเชื่อมกับ ERP
ส่วน fact ด้านเงินควร normalize เป็น:

`plot_code + year + installment_no`

เมื่อเชื่อมกับ progress ให้ใช้ **มูลค่างวดจริงใน dataset** ไม่ควรสร้างมูลค่างวดจาก template % อย่างเดียว

## Data quality / จุดที่ต้องระวัง

1. ชีตปี 2 ชื่อ `BOQ ป่าใหม่ 65 5 ปี2` มีเลข `5` แทรกอยู่ในชื่อชีต
2. ชีตปี 2 หัวงวดที่ 3–4 ระบุ `ปีที่ 3` ทั้งที่เป็นข้อมูลปี 2
3. ชีตปี 6 หัวคอลัมน์มูลค่าปีระบุ `ปี 5` แทน `ปี 6`
4. รหัสแปลงลำดับ 27 ใน source เป็น ` 38-STC` (มี leading space); dataset นี้ normalize เป็น `38-STC`
5. มีข้อยกเว้นของสัดส่วนงวด:
   - `27-VSD`, `28-VSD`, `29-VSD`, `38-VSD` มีหลายปีที่ใช้ 20% / 30% / 50% / 0%
   - `30-VSD` ใช้ 20% / 30% / 50% / 0% ในปี 3–6
6. ผลรวมงวด = มูลค่ารายปีทุกแปลง/ทุกปี (tolerance 0.01 บาท)
7. มูลค่ารายปีในชีตย่อยตรงกับชีตสรุปปี 1–10 ทุกแปลง
8. เลขลำดับ 1–160 ครบ ไม่มีซ้ำ และเลขที่สัญญาไม่ซ้ำในชุดนี้

## หมายเหตุ

ค่า `is_exception_to_header_template=true` หมายถึงสัดส่วนงวดในเซลล์จริงไม่ตรงกับ template ที่เขียนในหัวตาราง
แต่ dataset เก็บค่าจริงจาก workbook โดยไม่แก้ให้เป็น template
